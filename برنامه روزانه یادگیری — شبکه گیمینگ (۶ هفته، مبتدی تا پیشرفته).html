برنامه یادگیری — پروژه Gaming Network (نسخه ۲: از مبتدی تا سطح پیشرفته)

این نسخه اصلاح‌شده‌ست: هفته‌های اول سریع‌تر و فشرده‌تر شدن (چون فرض بر اینه پایه‌ات خالی نیست)، و از هفته سوم به بعد سطح واقعاً بالا می‌ره — چیزهایی که سرویس‌های واقعی گیمینگ (ElitePing/GodPing/ExitLag) واقعاً ازشون استفاده می‌کنن، نه فقط یک Tunnel ساده. مباحث مبتدی حذف نشدن، فقط فشرده‌تر و کم‌حرف‌تر ارائه شدن تا جا برای عمق باز بشه.

ساختار کلی برنامه (۶ هفته، ۴۲ روز):

  • هفته ۱: پایه لینوکس/امنیت/ابزار — فشرده
  • هفته ۲: Baseline و تحلیل مسیر واقعی
  • هفته ۳: WireGuard + Tuning دقیق (Kernel-level)
  • هفته ۴: Obfuscation واقعی (Xray/Reality) + Multi-protocol
  • هفته ۵: Observability (Monitoring واقعی) + Containerization
  • هفته ۶: Routing پیشرفته سمت Client + Load-testing + سخت‌سازی امنیتی نهایی

نقشه تکنولوژی‌ها (مرجع کلی — قبل از شروع بخون)

شبکه (Networking)

  • پایه: TCP/UDP, ICMP, Latency/Jitter/Loss/Burst Loss, NAT, CGNAT, MTU/MSS, Route/Traceroute
  • سطح متوسط: DNS (recursive vs authoritative, DNS resolution چطور روی لتنسی اثر می‌ذاره)، QUIC (پروتکل HTTP/3، چون بعضی بازی‌ها و سرویس‌ها ازش استفاده می‌کنن)، IPv6 پایه
  • سطح پیشرفته: BGP concept (فقط مفهوم مسیریابی بین AS ها، نه پیاده‌سازی)، Anycast concept، QoS و Traffic Shaping (tc, HTB/FQ-CoDel)، Congestion Control algorithms (Cubic vs BBR)
  • مخصوص گیمینگ: چرا Burst Loss بدتر از Average Loss حس می‌شه، مفهوم Jitter Buffer در بازی‌های آنلاین

لینوکس (سمت VPS)

  • پایه: User/permission/sudo، systemd، journalctl، ufw
  • سطح متوسط: nftables (جایگزین مدرن iptables)، sysctl kernel tuning (net.core.*, net.ipv4.tcp_*)، cron/systemd timers
  • سطح پیشرفته: Docker/Podman برای ایزوله‌سازی سرویس‌ها، bash/Python scripting برای عملیات خودکار، log aggregation

Tunneling / VPN

  • پایه: WireGuard ساده (Client-Server)
  • سطح متوسط: MTU/MSS Clamping دقیق، Multiple Peer، Keepalive tuning
  • سطح پیشرفته: Xray-core با پروتکل VLESS+Reality یا Shadowsocks-2022، مفهوم Multi-hop (Client → Relay1 → Relay2 → Game Server)، Domain Fronting / SNI masking (فقط مفهومی)

Observability / Monitoring

  • Prometheus (جمع‌آوری متریک)، Grafana (نمایش گرافیکی)، Node Exporter، Blackbox Exporter (برای ping/latency خودکار)
  • Loki یا فایل لاگ ساختاریافته برای متمرکز کردن لاگ‌ها

برنامه‌نویسی/اتوماسیون

  • Python: subprocess, asyncio (برای اجرای موازی چند تست شبکه هم‌زمان), pandas برای تحلیل، ذخیره در SQLite یا InfluxDB (time-series database مخصوص متریک)
  • API ساده (FastAPI یا Flask) برای اینکه بعداً بشه دیتای متریک رو از راه دور خوند

امنیت

  • SSH hardening، fail2ban، nftables rate-limiting، مفهوم WAF (برای فاز خیلی بعدتر اگه دشبورد وب داشته باشین)

نکته مهم: BGP واقعی، Anycast واقعی، ML-based Smart Routing، و SRE سطح Production هنوز جزو این فاز نیستن — فقط باید مفهومشون رو بشناسی، نه پیاده‌سازی کنی.

هفته ۱ — پایه فشرده (لینوکس + امنیت + ابزار)

روز ۱ — VPS + SSH Hardening + Key-based Auth

ssh-keygen -t ed25519 -C "mehdi-vps"
ssh-copy-id user@vps_ip

در /etc/ssh/sshd_config:

PasswordAuthentication no
PermitRootLogin prohibit-password
Port 2222   # تغییر پورت پیش‌فرض، یک لایه امنیتی ساده اضافه

یک کاربر غیر روت با sudo بساز. systemctl restart sshd.

روز ۲ — nftables (نه ufw ساده — مستقیم بریم سراغ ابزار واقعی)

به‌جای ufw، مستقیم nftables رو یاد بگیر، چون بعداً برای rate-limiting و NAT پیشرفته لازمش داری: 

sudo apt install nftables -y
sudo nft list ruleset

یک ruleset پایه بساز: /etc/nftables.conf

table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    ct state established,related accept
    iif lo accept
    tcp dport 2222 accept
    ip protocol icmp accept
  }
}

sudo nft -f /etc/nftables.conf و sudo systemctl enable nftables. همراهش fail2ban رو هم نصب و روی پورت جدید SSH تنظیم کن.

روز ۳ — File system، Log، و Kernel Parameters اولیه

journalctl، chmod/chown رو مرور کن (اگه بلدی رد شو، فقط تست کن دستورات یادت هست). علاوه بر این، یک نگاه به sysctl بنداز — این چیزیه که هفته‌های بعد جدی می‌شه: 

sysctl net.ipv4.ip_forward
sysctl net.core.rmem_max
sysctl net.core.wmem_max

فقط ببین این پارامترها چی هستن، هنوز تغییرشون نده.

روز ۴ — Network Interface، Route Table، و DNS

ip a
ip r
ss -tulpn
resolvectl status   # یا cat /etc/resolv.conf

یاد بگیر: تفاوت DNS recursive resolver با authoritative، و اینکه چرا یک DNS کند (مثل بعضی DNSهای داخلی) می‌تونه لتنسی قبل از شروع بازی اضافه کنه (connection setup delay). تست: dig game-server.com و مقایسه زمان جواب DNSهای مختلف (8.8.8.8 در برابر DNS ISP خودت).

روز ۵ — systemd Service + Timer (به‌جای فقط cron)

یک systemd service و یک systemd timer (جایگزین مدرن‌تر cron) بساز که هر ۵ دقیقه یک اسکریپت اجرا کنه. این پایه‌ی اتوماسیون هفته‌های بعده.

روز ۶ — Toolchain اندازه‌گیری کامل

sudo apt install mtr-tiny traceroute iperf3 tcpdump nmap -y

tcpdump رو این بار عمیق‌تر از قبل یاد بگیر — فیلتر زدن روی پورت و پروتکل: 

sudo tcpdump -i any udp port 51820 -n

این مهارت توی هفته ۳ برای دیباگ WireGuard حیاتیه.

روز ۷ — مرور نظری فشرده

TCP/UDP، Latency/Jitter/Loss/Burst Loss، NAT، CGNAT (تست با موبایل روی همراه‌اول/ایرانسل جدا — آیا IP عمومی واقعی داری؟)، و این‌بار اضافه کن: QUIC چیست (چرا بعضی سرویس‌ها دارن از UDP-based HTTP/3 استفاده می‌کنن و این چه ربطی به gaming/streaming داره).

هفته ۲ — Baseline واقعی + تحلیل مسیر عمیق

روز ۸ — انتخاب Scope (بازی‌ها/ISPها) + IPv6 Check

لیست بازی‌ها و ISPها رو بساز (مثل قبل)، ولی این‌بار چک کن هرکدوم IPv6 هم پشتیبانی می‌کنن یا نه (ping6, mtr -6) — چون مسیر IPv6 می‌تونه کاملاً متفاوت از IPv4 باشه.

روز ۹ تا ۱۰ — traceroute ICMP + UDP + TCP، مقایسه سه‌گانه

همون‌طور که قبلاً گفتیم: mtr، mtr -u، tcptraceroute رو برای هر بازی×ISP بزن و در یک جدول یکجا مقایسه کن. این‌بار به‌جای فقط ذخیره کردن خروجی خام، برای هرکدوم AS Number مربوط به هر hop رو هم پیدا کن (با whois <ip> یا سایت‌هایی مثل bgp.he.net) تا بفهمی ترافیکت از کدوم شبکه‌های Transit رد می‌شه.

روز ۱۱ تا ۱۲ — Baseline رسمی (RTT + iperf3 UDP Jitter) در بازه‌های زمانی مختلف

مثل قبل، ولی این‌بار iperf3 رو با پارامترهای دقیق‌تر بزن (شبیه‌سازی نرخ بسته واقعی بازی، نه فقط bandwidth عمومی): 

iperf3 -c <vps_ip> -u -b 1M -l 100 -t 60   # بسته‌های کوچیک، شبیه ترافیک بازی

پرچم -l 100 یعنی سایز بسته ۱۰۰ بایت، نزدیک‌تر به واقعیت پکت‌های game state.

روز ۱۳ — تحلیل: Domestic / Transit / Destination + AS Path

جدول قبلی رو با ستون AS Path تکمیل کن. سعی کن بفهمی مشکل واقعاً کجاست: زیرساخت داخلی، یک Transit خاص بین‌المللی، یا خود دیتاسنتر مقصد.

روز ۱۴ — جمع‌بندی + انتخاب Candidate Route

بر اساس داده‌ها، مشخص کن VPS فعلی‌ت (لوکیشن، Provider) بهترین انتخابه یا باید یک VPS دوم در لوکیشن دیگه هم تست کنی (مثلاً فنلاند یا فرانسه به‌جای فقط آلمان) تا مسیر رو مقایسه کنی.

هفته ۳ — WireGuard + Kernel-Level Tuning (سطح بالاتر از یک تانل ساده)

روز ۱۵ تا ۱۶ — نصب و اتصال پایه (سریع رد شو اگه هفته قبل تمرین کردی)

نصب سرور/کلاینت WireGuard، تست اتصال با curl ifconfig.me، باز کردن پورت روی nftables (نه ufw).

روز ۱۷ — MTU/MSS Clamping دقیق (سطح فنی، نه فقط عدد گذاشتن)

به‌جای فقط گذاشتن MTU = 1420، یاد بگیر MSS Clamping رو در سطح nftables/iptables انجام بدی تا برای TCP هم به‌صورت خودکار درست بشه: 

nft add rule inet filter forward tcp flags syn tcp option maxseg size set rt mtu

و برای پیدا کردن MTU دقیق مسیر (نه فقط حدس)، از Path MTU Discovery استفاده کن: 

ping -M do -s 1472 8.8.8.8   # کم کردن تدریجی سایز تا جواب بگیری

روز ۱۸ — Kernel Network Tuning (این روز کاملاً جدیده و سطح بالاتره)

پارامترهای sysctl که مستقیم روی throughput/latency اثر می‌ذارن رو تنظیم کن: 

net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
net.core.rmem_max = 26214400
net.core.wmem_max = 26214400

BBR الگوریتم congestion control گوگله که برای مسیرهای پرلتنسی و ناپایدار (دقیقاً وضعیت شبکه ایران) معمولاً بهتر از Cubic پیش‌فرض عمل می‌کنه. فعالش کن و با baseline قبلی (بدون BBR) مقایسه کن. 

sudo modprobe tcp_bbr
echo "tcp_bbr" | sudo tee -a /etc/modules-load.d/modules.conf
sysctl -p

روز ۱۹ — QoS / Traffic Shaping پایه با tc

یاد بگیر چطور با tc (traffic control) و الگوریتم fq_codel صف بسته‌ها رو مدیریت کنی تا Bufferbloat (که باعث lag ناگهانی زیر بار می‌شه) کاهش پیدا کنه: 

sudo tc qdisc add dev eth0 root fq_codel

این مفهوم رو تست کن: وقتی VPS همزمان یک دانلود سنگین و ترافیک بازی داره، آیا latency بازی بالا می‌ره؟ با و بدون fq_codel مقایسه کن.

روز ۲۰ — تست پایداری روی اپراتورهای مختلف + شروع مستندسازی Detection

مثل قبل تست کن WireGuard روی همراه‌اول/ایرانسل چقدر پایداره. این‌بار با tcpdump سمت کلاینت ببین آیا پکت‌های WireGuard قبل از رسیدن جواب throttle/drop می‌شن (نشونه‌ی DPI detection).

روز ۲۱ — مرور + مستندسازی مشکلات رایج

هفته ۴ — Obfuscation واقعی (اینجا سطح واقعاً بالا می‌ره)

روز ۲۲ — نصب Xray-core و فهم VLESS

به‌جای فقط خوندن تئوری Obfuscation، این هفته واقعاً پیاده‌ش می‌کنی:

bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)"

مفهوم VLESS رو یاد بگیر: یک پروتکل سبک‌تر از VMess که برای Reality طراحی شده.

روز ۲۳ — راه‌اندازی Reality (شبیه‌سازی TLS واقعی یک سایت معروف)

Reality با گرفتن SNI یک سایت واقعی (بدون نیاز به دامنه/گواهی خودت)، ترافیک رو طوری جا می‌زنه که از دید DPI شبیه یک اتصال HTTPS معمولی به یک سایت معتبره. کانفیگ سرور و کلاینت رو بساز و تست کن.

روز ۲۴ — مقایسه سه‌گانه: WireGuard خام vs Xray/Reality vs Shadowsocks-2022

همون Baseline (RTT/Loss/Jitter) رو این‌بار برای هر سه روش بگیر، هم روی وای‌فای هم روی موبایل‌نت (همراه‌اول/ایرانسل جدا). این مهم‌ترین جدول کل پروژه‌ته.

روز ۲۵ — مفهوم Multi-hop (Client → Relay → Game Server)

یاد بگیر (و اگه وقت داری، تست کن با دو تا VPS ارزون) که چطور ترافیک از یک Relay اول رد بشه و بعد به یک Exit Node دوم برسه. این باعث می‌شه اگه یک relay شناسایی/فیلتر بشه، کل سیستم از کار نیفته.

روز ۲۶ — SNI Masking و Domain Fronting (مفهومی)

فقط در حد فهمیدن مطالعه کن: چطور بعضی سرویس‌ها ترافیکشون رو پشت CDNهای بزرگ (Cloudflare و مشابه) پنهان می‌کنن. پیاده‌سازی کامل این خارج از scope فعلیه، ولی باید مفهومش رو بشناسی برای فازهای بعد.

روز ۲۷ تا ۲۸ — تثبیت Obfuscation Layer + تست نهایی پایداری چندروزه

کانفیگ نهایی (Xray/Reality + BBR + MTU tuning) رو برای ۲۴-۴۸ ساعت روشن نگه دار و پایداریش رو زیر نظر بگیر (قطعی‌ها، افت سرعت در ساعات پیک).

هفته ۵ — Observability واقعی (Monitoring Stack) + Containerization

روز ۲۹ — Docker پایه

curl -fsSL https://get.docker.com | sh
docker run hello-world

یاد بگیر Container چیست و چرا برای اجرای Prometheus/Grafana ایزوله و تمیز، از نصب مستقیم روی سیستم بهتره.

روز ۳۰ تا ۳۱ — Prometheus + Node Exporter

با docker-compose یک Prometheus بالا بیار که متریک‌های سیستم (CPU، RAM، Network) رو از VPS جمع کنه.

روز ۳۲ — Blackbox Exporter (Ping/Latency خودکار به‌جای اسکریپت دستی)

به‌جای اسکریپت Python هفته قبل (که همچنان به‌عنوان backup خوبه)، Blackbox Exporter رو کانفیگ کن تا هر چند ثانیه یک‌بار خودش ping/latency به سرورهای بازی رو اندازه بگیره و به Prometheus بده.

روز ۳۳ تا ۳۴ — Grafana Dashboard

یک Dashboard بساز که RTT/Jitter/Loss هر بازی×ISP رو به‌صورت گراف زنده نشون بده. این دقیقاً همون چیزیه که برای گزارش به تیم و تصمیم‌گیری روزانه لازمه — دیگه نیازی به نگاه کردن فایل CSV خام نیست.

روز ۳۵ — مرور + مستندسازی معماری Monitoring

هفته ۶ — Routing پیشرفته سمت Client + Load Testing + سخت‌سازی نهایی

روز ۳۶ تا ۳۷ — Policy Routing واقعی (پیاده‌سازی، نه فقط مفهوم)

این‌بار واقعاً پیاده‌سازی کن: فقط ترافیک یک بازی خاص (بر اساس IP مقصد یا پورت) از تانل رد بشه، بقیه ترافیک از مسیر عادی: 

ip rule add fwmark 100 table 200
ip route add default via <tunnel_gw> table 200
nft add rule ... meta mark set 100  # برای ترافیک مشخص

این دقیقاً چیزیه که شهریار سمت Client بهش نیاز داره — اگه تو این رو از سمت سرور/تئوری بلد باشی، هماهنگی خیلی بهتر می‌شه.

روز ۳۸ — TUN Interface دستی

یک TUN interface ساده بساز و ببین چطور پکت‌های IP خام رو می‌شه از یک برنامه userspace خوند/نوشت (حتی با یک اسکریپت پایتون ساده با کتابخونه pytun یا مشابه). این فهم عمیق‌تری از چیزی می‌ده که WireGuard/Xray زیر پوسته انجام می‌دن.

روز ۳۹ — Load Testing و رفتار زیر فشار

با iperf3 چند استریم هم‌زمان (-P 4) بزن و ببین سیستم زیر بار سنگین (شبیه‌سازی چند کاربر هم‌زمان) چطور رفتار می‌کنه. Latency بازی زیر بار چقدر بدتر می‌شه؟

روز ۴۰ — سخت‌سازی امنیتی نهایی (Rate Limiting در nftables)

nft add rule inet filter input tcp dport 2222 limit rate 5/minute accept

جلوگیری از brute-force و ساده‌ترین نوع سناریوهای DoS در سطح پورت.

روز ۴۱ — یکپارچه‌سازی کامل + تست End-to-End

همه‌چیز با هم: BBR + MTU/MSS Clamping + Xray/Reality + fq_codel + Policy Routing + Monitoring زنده. یک تست کامل ۲۴ ساعته بگیر و از Grafana Dashboard گزارش بگیر.

روز ۴۲ — گزارش نهایی برای متین و شهریار + برنامه فاز بعد

سند نهایی شامل:

  1. مقایسه سه‌گانه پروتکل‌ها (WireGuard خام / Reality / Shadowsocks) با عدد
  2. تاثیر BBR و QoS tuning روی Latency/Jitter
  3. معماری Monitoring و لینک Dashboard
  4. جمع‌بندی Policy Routing برای هماهنگی با کار شهریار
  5. پیشنهاد برای فاز بعد (احتمالاً: Multi-gateway واقعی، Load Balancing بین چند Exit Node، شروع فکر کردن به معماری کلاینت نهایی)

نکته پایانی

این نسخه دیگه یک "آموزش مقدماتی شبکه" نیست — تا آخرش، تجربه عملی با ابزارهایی داری که واقعاً پشت سرویس‌های تجاری گیمینگ هستن (Xray/Reality، BBR، fq_codel، Policy Routing، Prometheus/Grafana). اگه جایی احساس کردی خیلی سریع پیش رفتیم، همون روز رو تکرار کن — سرعت بالاتر رفتن مهم‌تر از رد کردنه، ولی عقب انداختن بی‌دلیل هم نکن.
